Follow the mechanism

One coefficient is shared. One is free.

At the target, either coefficient can supply the requested increase. At the protected input (1, 0), only the first coefficient contributes. Holding that coefficient fixed leaves the second available to satisfy the request.

Fit the target alone

The minimum Euclidean-norm exact update splits the increase equally: (0.5, 0.5). It reaches 3 at the target and shifts the protected output to 1.5.

Constrain what must stay

Set the first change to zero. The update (0, 1) reaches 3 and preserves the protected output. With no bias change, it also preserves every input on x₂ = 0.

Notice impossible requests

Protecting the target requires its change to be zero; the request requires +1. Protecting both coordinate directions also forces a no-op. Neither can satisfy the target request.

What carries over to the framework?

For a fixed feature map and a linear head, the output change is the dot product of the actual update and the feature vector. Zero change on protected feature directions extends to their span. More independent protection can leave fewer directions available for an edit.

The real implementation must also check the stored endpoint. Numerical fitting, dtype projection, or a changing feature extractor can invalidate an argument made only about the intended update. A small residual is a measured quantity with a scope; it is not exact preservation.

This is an illustration, not an experiment. The model and solution are supplied. There is no learned representation, live LLM, sampled population, or native floating-point certificate here.

The saved synthetic study supports a target–retention tradeoff for its declared methods and population. This geometry does not strengthen that empirical claim.
