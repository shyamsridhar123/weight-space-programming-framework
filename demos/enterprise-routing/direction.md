# Direction contract

## Scope and visitor mode

Operate / Read. A guided local enterprise demonstration and an actual captured
browser walkthrough. The user requested a nice, simple interface, framework
concepts, the enterprise use case, and impact. That precise brief governs the
design; no separate aesthetic approval is needed to execute it.

## Product mechanism and audience

Technical decision makers inspect a policy change by following the exact parent,
literal edit, realized candidate, protection evidence, admission, and rollback.
The record is synthetic. No production benefit is asserted.

## Chosen direction

A quiet change-review sheet with one persistent walkthrough rail and one main
reading surface. Light paper, dark green ink, serif headings, restrained green
for passing gates, and amber for blocked gates. Tables carry comparisons; a
weight matrix makes the single coefficient visible. Candidate 5 in the grounded
direction list is the change-review sheet. Seed key: 1df67527.

The considered grounded list: a release checklist, an experiment notebook, a
support queue console, a policy diff, a change-review sheet, a decision log, and
a model artifact inspector. All serve the same fixed simple-interface brief.

## First viewport and signature interaction

The goal and protection obligation appear side by side, followed by the current
and desired route. Navigation follows goal, candidate comparison, protection,
sealed decision, impact, and rollback. The signature moment is applying the
actual inverse and seeing the exact restored identity.

## Constraints and quality bar

Readable desktop framing, a responsive mobile layout, working keyboard focus,
actual Python execution, error recovery, scope statements, downloadable full
evidence, no external providers, and no Mermaid. This is a code-led build from
the pinned simple-interface brief; there is no approved image comp. The recording
captures the browser directly, rather than presenting generated animation as
screen footage.

## Open decisions

No product decisions block execution. A silent, readable walkthrough with in-UI
explanations is the default because the user did not request a narrator.
