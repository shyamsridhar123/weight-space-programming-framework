# Weight Space Programming Framework — v0.2.0-draft.3

This research draft rewrites the documentation around a question a reader can
inspect: **how can an edit change a requested output while preserving a declared
part of the model's behavior?** It applies the pinned STE-Pro-Max guidance to
the explanations, evidence, and visual artifact. Document length and verification
totals are not used to support technical or scientific claims.

## Start from a concrete edit

For weights `(1, 1)`, the worked example raises the output at `(1, 1)` from
2 to 3 while preserving the output at `(1, 0)`. A minimum Euclidean-norm exact
target-only update gives weights `(1.5, 1.5)` and changes the protected output
to 1.5. The protected edit gives `(1, 2)` and keeps it at 1. Protecting the
target itself makes that requested change incompatible with protection.

The [worked guide](https://github.com/shyamsridhar123/weight-space-programming-framework/blob/v0.2.0-draft.3/docs/weight-space/v2/worked-example.md) derives these
outcomes, runs them through the API, and explains why positive ridge and native
precision add separate obligations. The runnable
[session example](https://github.com/shyamsridhar123/weight-space-programming-framework/blob/v0.2.0-draft.3/examples/session_edit.py) follows validation, caller-defined
selection, sealing, and evaluation. Its analytic rows are an interface
illustration, not a held-out scientific result.

Download the [interactive explanation source](https://github.com/shyamsridhar123/weight-space-programming-framework/blob/v0.2.0-draft.3/artifacts/explanations/edit-retention/index.html)
and open the HTML file locally to change the edit and protected set. Its static comparison,
mechanism diagram, and explanation remain readable without JavaScript.
The lifecycle, architecture, and evidence flowcharts are PNG/SVG images.

## Connect the mechanism to the evidence

The framework remains generic: common interfaces support reading, diagnosing,
editing, and creating weights through explicit semantic/task adapters. RTS is
a retained historical application. The source review explains what the original
author report established, its reported limitations, and how the local study
differs from it.

The saved synthetic study supports a target–retention tradeoff. Soft retention
reduced mean collateral NRMSE from `0.888351` under target-only ridge editing to
`0.199321`; mean target NRMSE rose from `0.038695` to `0.360218`. Lower is better
for both metrics. Both errors divide by the RMS of the requested shift
`(0.6, -0.3, 0)`, `sqrt(0.15)`. These are dimensionless errors, not success rates.
Only output heads over supplied synthetic feature maps were trained and edited.

The [results guide](https://github.com/shyamsridhar123/weight-space-programming-framework/blob/v0.2.0-draft.3/docs/weight-space/v2/results.md) keeps the paired
world-cluster uncertainty, family differences, unmatched gradient compute,
full-protection no-ops, small realized residuals, precision effects, and repeated
edit failures alongside that comparison. The historical negative RTS result
remains available. No live LLM/provider arm or useful large-model editing result
is claimed.

The [proof guide](https://github.com/shyamsridhar123/weight-space-programming-framework/blob/v0.2.0-draft.3/PROOFS.md) explains the premises behind feature-span
preservation and sequential drift bounds. Conditional real-valued results do
not establish automatic candidate binding, extractor/compiler correctness, or
all-input floating-point execution. The [research plan](https://github.com/shyamsridhar123/weight-space-programming-framework/blob/v0.2.0-draft.3/ROADMAP.md) turns
these gaps into questions with proposed controls and acceptance/rejection criteria.

## What this revision checks

The current distribution is `0.2.0.dev3`. Its wheel was built and installed in
a fresh core-only environment outside the source checkout. Isolated imports,
the copied examples, dependency checks, and CLI entry points succeeded. The
worked guide's exact Python fences also ran against that installed wheel.

The original interactive script passed an independent arithmetic review.
Browser review covered its presets, protected-set choices, reset, themes,
desktop and narrow layouts, reduced motion, print emulation, and no-JavaScript
reading. Native keyboard activation and slider dragging remain unverified;
the review does not certify accessibility or reader understanding.

Original document bytes, implementation, frozen evidence, and proof inputs
remain traceable. This is a documentation revision with a refreshed distribution,
not a new scientific study or Lean proof run. Historical failures and successful
runs retain their own scope. The
[revision record](https://github.com/shyamsridhar123/weight-space-programming-framework/blob/v0.2.0-draft.3/provenance/documentation-revision.json),
