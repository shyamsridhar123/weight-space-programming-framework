**Main live studies: weight access and blind diagnosis**

**Evidence review: November 8, 2026, America/Chicago.** The main live study did not establish useful primary weight editing. All **80 of 80 primary weight-access assignments abstained**, leaving target gain, protected net harm, and joint useful coverage at zero in every parameter view. The frozen feasibility requirements remain **0.10 target gain, at most 0.01 protected net harm, and 0.75 useful coverage**. Zero harm from an unchanged parent does not satisfy the gain or coverage requirements. These are project feasibility margins, not demonstrated customer savings or service guarantees. The [weight-access protocol](../../experiments/research/live-studies/weight-access-protocol.json) and [evaluation manifest](../../artifacts/research/live-studies/evaluation/manifest.json) retain the design and negative result.

The blind-diagnosis study produced a descriptive mean proposed-minus-matched-control gain of **0.0283333**, with a saved 95% Student-t interval of **[−0.0191722276, 0.0758388943]** over six paired training-lineage means. Its mean joint useful coverage was **0.0833333**, below the same frozen 0.75 requirement. The interval crosses zero, and the result does not establish the prespecified useful causal-repair claim. Diagnosis and repair were selected together, so this experiment also leaves the original requirement for separate diagnosis and repair selection unmet. The [diagnosis protocol](../../experiments/research/live-studies/blind-diagnosis-protocol.json) explicitly records that joint boundary; the [issue acceptance assessment](issue-acceptance-status.md#issue-9) retains the separate-experiment gap.

The result is accompanied by successful saved evaluation, frozen replay, and independent artifact comparison. The comparison records **224 matching deterministic payloads and zero mismatches**, with every assignment retained. Repeatability of this negative study is useful evidence about the released computation and accounting. It does not turn the result into a useful edit, prove the provider's hidden computation, or reproduce the original author benchmarks or the methods reviewed in the primary papers. The [selected source review](../weight-space/v2/source-review.md), [full primary-paper review](primary-paper-review.md), and [original-source repeat report](original-source-repeat.md) describe those separate evidence populations.

The protocols designate both studies as resource-capped estimation, locally frozen rather than externally preregistered. They use six independently initialized and trained complete BANKING77 encoder/head lineages, `banking77-main-full-7001` through `banking77-main-full-7006`, with shared fixed public requests. The two semantic families were selected without inspecting these main families' error tables or heldout outcomes and were disjoint from the four pilot-selected families. The [pre-call label amendment](../../experiments/research/live-studies/label-amendment.json) maps the intended pending-transfer family from `pending_bank_transfer` to the dataset label `pending_transfer`; it records a spelling correction, no task reselection, and no modification of the original protocols. The other target is `card_payment_wrong_exchange_rate`. The [protocol lock](../../experiments/research/live-studies/protocol-lock.json) binds the two protocol identities.

Both studies supplied substantial matched context: trained affine-readout architecture, ordered feature and output names, native float32 semantics, a fixed output-to-queue mapping, encoder and preprocessing identities, an explicit target policy, up to four target-role labeled feature rows, and up to eight protected-role labeled feature rows. This tests what parameter access adds to a contextualized task. It does not test anonymous-array understanding or inference without data. Clean or planted mechanism identity, pilot confusion tables, fitted deltas in primary arms, evaluation features/labels/predictions, and descriptions of injected locations were forbidden context.

The five parameter views were `none`, `summary`, `rounded`, `subset`, and `exact`. Rounded values used three decimals. The subset fixed every eighth hidden feature in each output row plus every output bias by shape, before inspecting values. The primary proposer was configured for JSON-only output with native tools disabled, no brokered forward computation, regression, optimizer, fitting, or target execution. One candidate or explicit abstention was committed before the trusted harness sealed it, without endpoint feedback. The provider configuration requested OpenAI `gpt-6.1-sol`, low reasoning effort, a 180-second timeout, and zero retries. A deployment revision and hidden model computation were not observed. These are the recorded interface rules and configuration, not an operating-system or network isolation attestation or proof that the model performed no internal arithmetic.

The evidence supports concrete next work, with new protocols rather than retrospective changes to these margins. The fuller [research directions](next-directions.md) provide the task and issue dependencies.

1. **Resolve provider delivery and audit coverage before estimating broad editor reliability.** Use a separately declared development attempt to investigate coarse transport failures, retain actual terminal and usage records, then freeze failure handling, retry limits, independent construction/session units, and delivery expectations before new untouched evaluation. Preserve this study's 90 failures. Match semantic context, examples, summaries, weights, metadata/hint ablations, validation opportunities, and forward/fitting budgets across access arms. A useful final endpoint can support a narrower behavior claim when access evidence is incomplete, but cannot repair an unauditable access claim.

2. **Separate ownership changes from recognition repairs.** Compare an unchanged classifier plus queue-policy overlay with context routing, target-only fitting, retained head edits, and tuned head retraining.
