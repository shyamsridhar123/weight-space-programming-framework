**How resource controls act.** The broker's source defaults are `max_requests=100` and `max_request_bytes=1_000_000`; constructor overrides are permitted and validated. The [`_request_limits` helper](../../rlcd/weight_space/broker.py#L120) constructs a fresh dictionary from the stored invocation values used by the request checks, including overrides. The dictionary is a returned record, not a way to reconfigure those stored integer bounds. This construction does not make the entire broker immutable. The byte check occurs after finite-JSON normalization/canonical serialization and measures the canonical request, not incoming transport bytes or peak memory. The event-count check denies further supported operations after the allowance; denials still append events. It therefore supplies neither a bounded event-log size nor a CPU/memory bound. Failed lowering consumes an attempted opaque-handle slot even if no session candidate was produced. `attempted_submissions` and session `usage.proposals` have different meanings. See the [request path](../../rlcd/weight_space/broker.py#L163) and [audit payload](../../rlcd/weight_space/broker.py#L261).

The limits record is added to broker metadata and audit only. Neither request bound is added to `wsp-session-config/1`, and the session's [configuration identity](../../rlcd/weight_space/workflow.py#L555) remains a hash of the existing session configuration. The broker constructor still supplies the same session arguments; this change does not expand that session identity to commit the broker's separate request bounds. The audit's new `request_limits` object is inside its own hash-covered payload.

The session [checks projected usage before admission](../../rlcd/weight_space/workflow.py#L629). Over-budget requests record requested charges and admit none; an operation that fails after admission retains its charge. Provider [usage admission](../../rlcd/weight_space/live_provider.py#L322) occurs after the call and requires both nonnegative integer token counters. Independently valid usage can be charged before a failed attempt stops the driver; missing usage is not admitted as zero. A budget denial is not proof of zero external consumption. Tokens are provider-supplied counters, not a local measurement or a pre-call token ceiling. Heldout callback work is [counted separately](../../rlcd/weight_space/workflow.py#L943), outside the proposer budget; callback-internal work is unobserved. Financial amounts remain explicitly unknown in the provider receipt. There is no finite total-cost guarantee.

**CLI requests and host controls.** [`TOOL_FREE_CONFIG`](../../rlcd/weight_space/live_provider.py#L25) requests disabled native tools/features, plugins and MCP servers. The [command](../../rlcd/weight_space/live_provider.py#L214) adds ignored user config/rules, an ephemeral session, a requested read-only sandbox for the tool-free route, no interactive approvals and a separate proposer working directory. Configuration and command identity are recorded. The [event parser](../../rlcd/weight_space/live_provider.py#L116) labels observed non-reasoning/non-message tool items unapproved; a tool-free attempt with such items cannot complete. This detects observed events after they occur. It does not independently establish that the CLI honored every flag, that all actions appeared in the stream or that hidden model computation obeyed a semantic policy. A working directory, output schema, command hash and disabled-tool request do not install host isolation.

**Old-transcript replay caveat.** Adding fields to a successful metadata response changes its canonical bytes. The [broker event constructor](../../rlcd/weight_space/broker.py#L125) commits the response and previous event hash, so newly emitted metadata events and subsequent hash links differ from equivalent pre-change events. The [saved-attempt replay comparison](../../scripts/run_broker_trial.py#L143) requires canonical response equality after its explicit candidate-handle translation. A pre-change transcript containing successful metadata without the new fields therefore must not be promised to replay unchanged through the modified broker. A newly constructed audit also has different bytes when the limits object is added, even if its session identity, chosen endpoint and evaluation agree. Historical evidence retains its recorded schema, bytes and source identity; an unchanged `/1` outer schema does not by itself establish cross-revision replay compatibility. Use the corresponding pinned implementation for an old transcript, or separately specify and verify an explicit compatibility path. This increment implements no silent migration or record backfill; no historical rerun or compatibility-path test was performed for this inventory.
