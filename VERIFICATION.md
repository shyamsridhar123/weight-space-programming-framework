definitions. Keep the question and its evidence together.

## Match the check to the claim

| Question | Relevant check | Boundary of a passing result |
| --- | --- | --- |
| Can a reader run the documented example? | Execute the example with the stated dependencies and inspect its output and assertions | The example works in that environment. It does not establish a scientific effect or validate every use of the API |
| Does the implementation satisfy its retained executable checks? | Run the Python suite against identified source and test bytes | The exercised cases pass. This does not prove complete coverage, population generalization, or all-input correctness |
| Does the distribution work outside the source checkout? | Build a wheel, install it in a fresh environment, and run imports, examples, dependency checks, and CLI entry points | The identified wheel works in the exercised environment. An editable source install alone cannot establish this |
| Do the formal statements elaborate with the permitted assumptions? | Build `WeightSpace.GenericAudit` and run its separate transitive axiom audit | The supplied real-valued statements check under their hypotheses and trusted toolchain. Runtime extraction and numerical execution remain separate obligations |
| Can the reported saved-data results be recomputed? | Replay the saved-evidence auditor with explicit freeze and protocol identities | The declared equations and records agree within their specified exact or numerical checks. Replaying observed worlds does not provide new experimental units |
| How are originals and public derivatives distinguished? | Resolve original archive mappings, validate the sanitation ledger, and exercise mismatch rejection | Unchanged inputs retain their expected hashes; changed or omitted inputs have explicit bindings. Derivative validation does not establish original-byte preservation or replay |
| Does the published tree match its manifest and preservation inventory? | Run the publication verifier after the tree and manifest are frozen | The supplied tree passes the verifier's integrity and destination checks. This is not a scientific review or an independent execution attestation |
| Did the hosted workflow complete for this commit? | Inspect the actual hosted run, job conclusions, commit identity, and bound logs | That workflow completed on the identified runner and commit. Local workflow syntax checks do not establish hosted execution |

## Repeat a check without changing the historical record

Start from the intended commit and follow [REPRODUCING.md](REPRODUCING.md) for
environment setup, the standalone suite, examples, packaging, and saved-evidence
replay. Follow [PROOFS.md](PROOFS.md#fresh-clone-procedure) for the pinned proof
procedure. Historical command and environment records retain their execution
scope, with internal locators redacted as listed in the sanitation ledger.
Use the current portable commands rather than treating a redacted workstation
path as a runnable instruction.

Use a new output directory for each attempt. Keep reviewer outputs under new
`.runs/` or `.proof-runs/` paths. For pytest, choose an unused repository-local
`--basetemp`; pytest clears that directory before use, so it must contain no
work or retained evidence. Current root guides supersede older commands inside
preserved research documents.

For an installed-wheel check, use a fresh environment outside the source
checkout's import path. Record the wheel hash, require imports to resolve
inside that environment, and exercise the documented example and CLI entry
points. The core-only path should also verify that Torch is absent. Record the
registry actually used and preserve failed retrieval attempts. The
[publication workflow](.github/workflows/publication-python.yml) supplies the
executable installation check.

Run the saved-evidence auditor with the explicit expected freeze and protocol
identities given in the reproduction guide. A disclosed public derivative
does not waive its original-byte checks or guarantee a successful replay.
Keep exact identity checks separate from numerical tolerances. An interrupted
replay is incomplete even if its
progress log has no failures. A new study needs a different output tree and an
honestly labeled protocol; it must not overwrite the observed study or its
receipts.

After the guides and archived verification files are frozen and
`MANIFEST.sha256` is generated, run the standard-library publication verifier
on that exact tree:

```bash
python scripts/verify_publication.py --out .runs/reviewer-publication-1.json
```

A preflight result obtained while files are still changing cannot substitute
for this final check. The verifier's local-link checks concern destinations;
fragment navigation, browser behavior, and explanation quality need their own
review.
